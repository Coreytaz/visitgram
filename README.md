# Visitgram

Visitgram (Визитграм) — аналитика сайтов с уведомлениями в Telegram на основе [Analog](https://github.com/orangecoloured/analog), MIT.
Скрипт сайта → Node.js → база данных через Drizzle ORM → Telegram через [grammY](https://grammy.dev/). По умолчанию используется локальная SQLite; веб-панели нет.

Один grammY `Bot` принимает команды и inline-кнопки через long polling и отправляет уведомления через `bot.api.sendMessage`. Работают HTML-оформление, таймаут 10 секунд, очередь в выбранной БД и `retry_after`. Polling принимает `message` и `callback_query`, использует запросы по 5 секунд и повторный запуск при сбоях. Нужен только исходящий доступ к Telegram; webhook не требуется. Запускайте только один экземпляр бота.

## Установка без Docker

Подробная [инструкция по запуску и созданию структуры БД](docs/SETUP.md):
Windows и Linux/macOS, SQLite, libSQL/Turso, PostgreSQL, MySQL, SingleStore,
MSSQL и CockroachDB; создание баз и пользователей, права, миграции и диагностика.

Нужны Node.js 24 LTS (от 24.5) и npm.

```bash
npm ci
cp .env.example .env.local
chmod 600 .env.local
nano .env.local
npm start
```

Сборка фронтенда не нужна. `npm run dev` запускает сервер с перезагрузкой при изменении кода.

В `.env.local` задайте `TELEGRAM_BOT_TOKEN`, свой личный `TELEGRAM_CHAT_ID`, случайный `VISITGRAM_TOKEN` и `VISITGRAM_PUBLIC_URL` — публичный HTTPS-адрес сервера трекера. Создайте бота в @BotFather и отправьте `/start`. Команды, ввод и кнопки доступны только отправителю с ID владельца в его личном чате; посторонние и группы не получают доступа. Если обе переменные Telegram пустые, HTTP-трекер продолжает работать без меню и отправки.

```dotenv
VISITGRAM_SQLITE_URL=file:./analytics.db
VISITGRAM_PORT_SERVER=3000
VISITGRAM_PUBLIC_URL=https://analytics.example.com
VISITGRAM_TOKEN=случайный_секрет_для_API
VISITGRAM_TRACK_RETENTION_DAYS=30
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=ваш_chat_id
```

Случайный токен: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
SQLite создаётся автоматически и использует локальный URL `file:`. Для неё отдельный сервер базы данных не нужен. Остальные подключения описаны ниже. Старые записи SQLite сохраняются; историческая таблица `analog`, если уже есть, не удаляется, но новые события и очередь записываются только в `tracking_events`.

## Архитектура Telegram-бота

Telegram-слой находится в `src/services/telegram/`. Фабрика `createTelegramBot({ token, owner, fetch? })` создаёт бота без запуска polling; транспорт можно подменить в тестах. Модули команд, главного меню, сайтов, шаблонов и текстового ввода экспортируют фабрики `Composer`. Сборка выполняется в `app.ts`, жизненный цикл polling — в `polling.ts`. Прежний серверный модуль Telegram остаётся фасадом для HTTP-сервера и очереди.

Порядок middleware: проверка владельца → команды → подтверждение callback → маршрутизация через официальный `@grammyjs/router` → текстовый ввод и резервные ответы. Router разделяет кнопки главного меню, сайтов и шаблонов; существующие `callback_data` сохраняются. Проверка формата выполняется до изменения состояния. При ошибке подтверждения callback действие прекращается.

Для новой команды добавьте обработчик в `createCommands` до возврата Composer:

```ts
commands.command("help", (ctx) =>
  ctx.reply("Откройте /menu для управления сайтами."),
);
```

Для нового функционального модуля экспортируйте фабрику Composer и подключите её в `createTelegramMiddleware` перед общими обработчиками текста. Показ и редактирование сообщений, HTML-экранирование и inline-клавиатуры общего назначения находятся в `ui.ts`. Состояние ввода и черновики остаются в БД с прежним сроком действия; плагины menu и conversations не используются. Глобальный auto-retry не подключён: повторами доставки, пятью попытками и `retry_after` управляет долговечная очередь БД.

Основы организации: [Composer-модули](https://grammy.dev/advanced/structuring), [Router](https://grammy.dev/plugins/router).

## Подключения Drizzle ORM

Используются закреплённые `drizzle-orm` и `drizzle-kit` версии **1.0.0-rc.5**. MSSQL и CockroachDB используют отдельные диалекты этой RC-ветки. Одновременно работает одно подключение и один процесс приложения. Совместимые облачные сервисы доступны по обычному протоколу выбранной СУБД; отдельные Cloudflare/Bun/мобильные и облачные HTTP-адаптеры не включены.

Выберите `VISITGRAM_DB_DIALECT` и `VISITGRAM_DATABASE_URL` в `.env.local`:

| Диалект       | Пример URL                                                             | Драйвер          |
| ------------- | ---------------------------------------------------------------------- | ---------------- |
| `sqlite`      | `file:./analytics.db`                                                  | `@libsql/client` |
| `libsql`      | `libsql://your-database.turso.io`                                      | `@libsql/client` |
| `postgresql`  | `postgresql://user:password@localhost:5432/analog`                     | `pg`             |
| `mysql`       | `mysql://user:password@localhost:3306/analog`                          | `mysql2`         |
| `singlestore` | `mysql://user:password@hostname:3306/analog`                           | `mysql2`         |
| `mssql`       | `mssql://user:password@hostname:1433/analog?encrypt=true`              | `mssql`          |
| `cockroachdb` | `postgresql://user:password@hostname:26257/analog?sslmode=verify-full` | `pg`             |

Для Turso задайте `VISITGRAM_DATABASE_AUTH_TOKEN`. Для локального libSQL разрешён `file:`. Пароли в URL кодируются по правилам URL; не публикуйте `.env.local`. Параметры TLS задавайте согласно настройкам вашего сервера и драйвера; для MSSQL также принимается обычная строка подключения `Server=...;Database=...;User Id=...;Password=...;Encrypt=true`.

Без `VISITGRAM_DATABASE_URL` используется `VISITGRAM_SQLITE_URL`, по умолчанию `file:./analytics.db`. Непустая `VISITGRAM_DATABASE_URL` имеет приоритет. Для остальных диалектов URL обязателен. Подключается только драйвер выбранной базы. Для облачного PostgreSQL/MySQL нужен прямой совместимый SQL endpoint с поддержкой транзакций.

### Миграции и обновление

Перед обновлением остановите приложение и сохраните резервную копию SQLite. Приложение применяет подготовленные миграции до запуска HTTP и Telegram. При ошибке миграции запуск прекращается; параметры подключения и запросы с данными в лог не выводятся.

```bash
npm run db:migrate
# После изменения единого описания колонок в scripts/schema-generate.mjs:
npm run db:generate -- --name=describe_change
```

`db:generate` обновляет конкретные TypeScript-схемы всех диалектов и создаёт миграцию для диалекта из окружения. Для изменения общей структуры повторите команду с нужными `VISITGRAM_DB_DIALECT` для каждого диалекта; libSQL использует SQLite-миграции. SQL и снимки схем в `drizzle/` сохраняются в Git. Файлы применённых миграций менять нельзя: при повторном запуске проверяется контрольная сумма. Не используйте `drizzle-kit push` для обновления существующей установки.

Старая SQLite обновляется на месте: сохраняются ID, JSON событий, статусы очереди, сайты, посетители, шаблоны и черновики. Поля для статистики заполняются из истории пакетами по 500 записей. Повреждённый JSON сохраняется; его производные поля остаются пустыми. Новая статистика использует обычные колонки вместо SQLite JSON-функций. Повторная миграция не пересоздаёт таблицы и не перезаписывает настройки.

Для новой серверной СУБД создайте отдельную пустую базу и пользователя с правами на миграции. Автоматического переноса данных между СУБД нет. Очистка истории по сроку хранения продолжает выполняться при обычном старте сервера.

### Проверки других СУБД

`npm test` проверяет SQLite, локальный транспорт libSQL и генерацию SQL для остальных пяти диалектов. Реальные интеграционные проверки используют только явно заданные тестовые подключения:

```dotenv
VISITGRAM_TEST_POSTGRESQL_URL=postgresql://user:password@localhost:5432/analog_test
VISITGRAM_TEST_MYSQL_URL=mysql://user:password@localhost:3306/analog_test
VISITGRAM_TEST_SINGLESTORE_URL=mysql://user:password@hostname:3306/analog_test
VISITGRAM_TEST_MSSQL_URL=mssql://user:password@hostname:1433/analog_test?encrypt=true
VISITGRAM_TEST_COCKROACHDB_URL=postgresql://user:password@hostname:26257/analog_test?sslmode=verify-full
# Необязательно: тест удалённого libSQL вместо локального транспорта
VISITGRAM_TEST_LIBSQL_URL=libsql://your-test-database.turso.io
VISITGRAM_TEST_LIBSQL_AUTH_TOKEN=token
```

Используйте отдельные тестовые базы: набор применяет миграции, создаёт свои сайты и удаляет свои записи после проверки. Переменные должны быть установлены в окружении тестового процесса; `.env.local` команда `npm test` не загружает. Без подключения соответствующий интеграционный тест явно пропускается. Компиляция SQL не заменяет проверку на живом сервере.

## Управление сайтами в Telegram

`/start` и `/menu` открывают главное меню: «Мои сайты» и «Добавить сайт». Список разбит на страницы по 8 сайтов. В карточке доступны код трекера, статистика, редактирование названия и доменов, настройки уведомлений, пауза и архив.

- При добавлении отправьте домен: `example.com` станет `https://example.com`. Для HTTP и нестандартного порта указывайте полный origin. Можно отправить до 10 origin через запятую; без пути, параметров, логина и `*`. `www` добавляется явно, один origin принадлежит одному сайту, включая архивные.
- Название можно изменить (до 80 символов); редактирование доменов заменяет весь список origin. Новые настройки действуют без перезапуска сервера.
- Просмотры и клики включаются в уведомлениях независимо. Отключение уведомлений сохраняет сбор в выбранной базе. Пауза останавливает сбор и отправку; при возобновлении прежние переключатели сохраняются.
- Архивирование с подтверждением сохраняет историю и допускает восстановление. Оно не удаляет сайт физически и не освобождает его домены. Восстановление сохраняет прежние настройки паузы и уведомлений.
- Статистика: последние 24 часа, 7 или 30 дней, просмотры, клики, уникальные браузеры, новые за период и известные до периода посетители, топ-5 страниц. Старые и временные ID показываются отдельно и не входят в число уникальных браузеров. Доступная история событий ограничена сроком хранения.
- Ввод названия/доменов сохраняется в БД на 10 минут. `/cancel`, кнопка отмены и переход в другое меню прекращают ввод. Архивный сайт нужно восстановить перед редактированием.

При первой миграции можно импортировать `VISITGRAM_ALLOWED_ORIGINS` (через запятую). `TELEGRAM_EVENTS=pageview,click` задаёт начальные уведомления импортированных сайтов. Миграция выполняется один раз, дальше источник настроек — выбранная БД; изменения этих переменных не пересоздают сайты. Новые сайты по умолчанию собирают события и уведомляют о просмотрах и кликах.

К старым событиям добавляется `site_id`: привязка выполняется только при однозначном соответствии host старого события импортированному сайту. Остальная история сохраняется без привязки; недоставленные события без привязки отключаются, чтобы не отправить их не тому сайту. Перед обновлением сделайте резервную копию SQLite при остановленном сервисе.

При необходимости HTTP-прокси задайте `HTTPS_PROXY` и `NO_PROXY=localhost,127.0.0.1`. Локальный адрес прокси Windows нельзя переносить на Ubuntu, если на ней такого прокси нет.

## Шаблоны уведомлений

Откройте `/menu` → «Мои сайты» → сайт → «Уведомления» → «📝 Шаблоны». Для каждого сайта есть общий шаблон и отдельные шаблоны просмотров и кликов. Сначала используется шаблон типа события, затем общий, затем стандартное оформление. Сброс удаляет только выбранное переопределение. Настройки независимы для разных сайтов и сохраняются в выбранной БД.

Нажмите «Изменить» и отправьте текст до 2000 символов. Бот проверит его и покажет предпросмотр на вымышленных данных. Изменение применяется только кнопкой «✅ Сохранить». Можно исправить, отменить, посмотреть переменные; для общего шаблона доступны предпросмотры клика и просмотра. Черновик хранится в БД 10 минут; переход в другое меню отменяет его. Архивные сайты нельзя редактировать.

```html
{action_emoji} <b>{site_name}</b>

{action} 📄 <code>{path}</code> 👤 {visitor_status} 🆔 <code>{visitor_id}</code>

🕒 {time}
```

| Переменные                                                                      | Значения                                                  |
| ------------------------------------------------------------------------------- | --------------------------------------------------------- |
| `{action}`, `{action_emoji}`, `{event_type}`                                    | Действие, эмодзи 👀/🖱, pageview/click                     |
| `{site_name}`, `{site}`                                                         | Название сайта и host события                             |
| `{path}`, `{title}`, `{element}`                                                | Путь, заголовок и название элемента                       |
| `{visitor_id}`, `{visitor_status}`                                              | Анонимный ID браузера, Новый/Повторный/Без постоянного ID |
| `{ip}`, `{browser}`, `{os}`, `{device}`                                         | Соединение и устройство                                   |
| `{language}`, `{timezone}`, `{screen}`, `{viewport}`                            | Язык, часовой пояс, экран и окно                          |
| `{elapsed_seconds}`, `{referrer}`                                               | Секунды до действия и источник перехода                   |
| `{utm_source}`, `{utm_medium}`, `{utm_campaign}`, `{utm_content}`, `{utm_term}` | UTM-метки                                                 |
| `{time}`                                                                        | Человекочитаемые дата и время с UTC-смещением             |

Поддерживаются переносы строк, эмодзи и теги `<b>`, `<i>`, `<u>`, `<s>`, `<code>`, `<pre>` без атрибутов. Теги должны быть правильно закрыты; `code` и `pre` не совмещаются с другими тегами. Значения переменных экранируются, отсутствующие заменяются на `—`, ноль сохраняется. Для буквальных скобок используйте `{{` и `}}`; для амперсанда — `&amp;`. Неизвестные переменные и неправильная разметка отклоняются. Условия, циклы и выполнение кода не поддерживаются.

Шаблон выбирается в момент отправки, поэтому обновление применяется и к ожидающим событиям очереди. Если шаблон повреждён или итоговый HTML-исходник превышает 4096 символов, отправляется стандартное уведомление; в журнал пишется краткая причина без данных события. Готовая HTML-разметка шаблона не обрезается. Повторная миграция сохраняет шаблоны и историю; существующие сайты продолжают использовать стандартное оформление, пока вы его не измените.

## Подключение сайта

Опубликуйте сервер через HTTPS reverse proxy (порт по умолчанию 3000). Ограничьте прямой внешний доступ к порту. Вставьте на свой сайт скрипт, при необходимости после согласия на аналитику:

```html
<script
  defer
  src="https://analytics.example.com/tracker.js"
  data-site-id="ID_ИЗ_БОТА"
></script>
<button>Купить</button>
<a href="/pricing">Тарифы</a>
```

Просмотры, переходы SPA и клики по кнопкам и ссылкам фиксируются автоматически, включая динамически добавленные элементы. Поддерживаются `button`, `[role="button"]` и `input` типов `button`, `submit`, `reset`. Название клика берётся из `aria-label`, `title`, текста элемента, ID или имени тега (до 120 символов); значения полей не считываются. Необязательный атрибут `data-analog-event="Купить"` задаёт своё название события. Для исключения области используйте `data-analog-ignore`. DNT и Global Privacy Control отключают сбор.

Готовый код с правильным ID выдаёт кнопка «Код трекера». ID передаётся параметром `site_id` в `/api/track`, он публичный и не заменяет проверку origin. Старый скрипт без ID работает, если origin однозначно связан с сайтом. Без `VISITGRAM_PUBLIC_URL` бот выдаёт локальный адрес `http://localhost:3000`: для установки на настоящем сайте задайте публичный HTTPS-origin без пути.

Уведомление содержит действие, сайт и страницу, заголовок, постоянный анонимный ID браузера, отметку «Новый / Повторный посетитель», IP непосредственного соединения, приблизительные браузер/ОС/тип устройства, язык, часовой пояс, экран и окно, время до действия, источник (origin), пять стандартных UTM-меток и человекочитаемое время с UTC-смещением. Поля форм, чужая история браузера и геолокация устройства не считываются. Query string и fragment исключаются, кроме перечисленных UTM. Не помещайте личные данные в пути, заголовки, метки и названия событий.

### Как считаются уникальные посетители

Трекер сохраняет случайный UUID в `localStorage` с ключом отдельного сайта. Он переживает перезагрузку, закрытие браузера и открытие новой вкладки. Новый браузер, инкогнито и очистка хранилища создают новый ID; IP и отпечаток устройства для объединения людей не используются. Между разными origin (например, `www` и доменом без `www`) хранилище не общее. Это оценка уникальных браузеров, а не точное число людей.

Посещение использует отдельный ID в `sessionStorage`: новая вкладка или 30 минут без событий начинают новый визит. В течение первого визита все события помечаются как новые; следующий визит известного браузера — повторный. Сервер определяет статус в транзакции БД, а не доверяет флагу «новый» от клиента. Если постоянное хранилище запрещено, остаётся временный ID вкладки или страницы, он явно помечен как непостоянный и не входит в уникальные браузеры. DNT/GPC отключают сбор и создание ID.

В статистике «Впервые за период» — браузеры, впервые замеченные в выбранном окне; «Известные до периода» — посетившие в этом окне браузеры с более ранним первым событием. Эти две группы в сумме дают уникальных браузеров. Повторное посещение внутри периода не увеличивает уникальных и не переносит нового посетителя во вторую группу.

Старые сессионные ID задним числом объединить нельзя. Для распознавания повторных визитов таблица `site_visitors` сохраняет только ID, сайт и время первого/последнего события, независимо от очистки подробного журнала. Записи `visitor_sessions` удаляются по сроку хранения событий. Загруженный ранее скрипт может оставаться в браузерном кеше до 5 минут; после обновления действует перепроверка кеша.

За reverse proxy IP будет адресом прокси: X-Forwarded-For не принимается на веру. Данные браузера могут быть подменены. Origin-фильтр — не проверка подлинности посетителя. Приём ограничен 120 событиями в минуту на адрес соединения (за прокси лимит общий). Запускайте один процесс, без cluster-режима.

Выбирайте типы уведомлений в карточке каждого сайта. При отключении типа, паузе и архивировании соответствующие ожидающие отправки события помечаются `disabled` и не возобновляются автоматически. Уже выполняющийся сетевой запрос отозвать нельзя.

## Диагностика

- `GET /health` → `{"status":"ok"}`.
- `GET /tracker.js` → скрипт сайта.
- `POST /api/track?site_id=…` → приём события с origin этого сайта; неизвестный/архивный сайт — 404, чужой origin — 403, пауза — 204 без записи.
- `GET /api/visits` → последние 100 записей, только с административным токеном; необязательный фильтр `?site_id=…`.
- `/`, старая панель и `/api/events` возвращают 404.

```bash
curl http://localhost:3000/health
curl -H "Authorization: Basic $VISITGRAM_TOKEN" http://localhost:3000/api/visits
```

`$VISITGRAM_TOKEN` в примере должен быть установлен в оболочке; файл `.env.local` автоматически туда не загружается. Basic здесь — исторический формат Analog: значение токена напрямую, без Base64. Не размещайте административный токен в скрипте сайта.

Очередь сохраняется в выбранной базе и переживает перезапуск. Отправка — один запрос примерно каждые 1,1 секунды, до пяти попыток, таймаут 10 секунд, задержка от 30 секунд с учётом Telegram `retry_after`. Статусы: `pending`, `sent`, `failed`, `disabled`. После пяти неудач событие остаётся в журнале как `failed`. Повторная доставка возможна при потере ответа Telegram. При большом потоке очередь может отставать.

Удаление записей старше `VISITGRAM_TRACK_RETENTION_DAYS` выполняется при старте и каждые 24 часа, включая старые недоставленные события. Для резервной копии остановите сервис перед копированием файла БД или используйте SQLite backup API.

## Автозапуск на Ubuntu

Расположите проект в `~/visitgram`. Создайте `~/.config/systemd/user/visitgram.service`:

```ini
[Unit]
Description=Visitgram tracker
After=network-online.target

[Service]
WorkingDirectory=%h/visitgram
ExecStart=/usr/bin/npm start
Restart=on-failure
RestartSec=5
UMask=0077
Environment=NODE_ENV=production

[Install]
WantedBy=default.target
```

Проверьте путь `command -v npm`: при необходимости замените `/usr/bin/npm`.

```bash
systemctl --user daemon-reload
systemctl --user enable --now visitgram
sudo loginctl enable-linger "$USER"
journalctl --user -u visitgram -f
```

## Локализация

Бот использует официальный плагин `@grammyjs/i18n` и каталоги Fluent в `src/services/telegram/locales/`: русский (`ru`) и английский (`en`). Интерактивные ответы выбирают язык по `language_code` пользователя Telegram; региональные варианты вроде `en-US` поддерживаются. Для неизвестного или отсутствующего языка используется русский. Язык вычисляется для каждого обновления, без изменения сохранённых черновиков.

`TELEGRAM_LOCALE=ru` или `TELEGRAM_LOCALE=en` задаёт язык уведомлений из очереди и стартового меню, у которых нет контекста пользователя. Фабрика бота принимает необязательный `locale` для явного выбора языка интерактивных ответов. Пользовательские шаблоны сохраняются без перевода; значения переменных действия, статуса посетителя и времени используют язык уведомления.

При добавлении текста используйте `ctx.t("ключ", { value1: значение })` и добавляйте одинаковый ключ в оба каталога. Динамические значения в HTML-сообщениях необходимо экранировать через `html` до передачи в перевод. Для сообщений вне контекста используйте `translator(locale)`.

## Дополнительные события

Трекер автоматически собирает события ниже. В Telegram: `/menu` → «Мои сайты» → сайт → «Уведомления» — отдельный переключатель для каждого типа. По умолчанию из новых событий уведомления включены только для `form_success` и `contact_click`; остальные сохраняются без отправки. Настройки просмотров и кликов сохраняются. Статистика за 1, 7 и 30 дней показывает количество событий и разбивку по порогам/этапам. Это количество срабатываний, а не число уникальных посетителей.

| Тип              | Условие                                                                                                         |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| `form_start`     | Первое пользовательское изменение поля формы за цикл заполнения                                                 |
| `form_success`   | Явное подтверждение успешной отправки через API ниже                                                            |
| `form_abandon`   | Уход со страницы / смена SPA-маршрута после начала без подтверждения успеха                                     |
| `scroll_depth`   | Достигнуты 25, 50, 75, 100% высоты документа по нижнему краю окна; короткие страницы без прокрутки пропускаются |
| `active_time`    | Накоплены 30, 60, 120, 300 секунд активности при видимой вкладке и взаимодействии за последние 30 секунд        |
| `block_view`     | Не менее половины отмеченного блока видно непрерывно одну секунду                                               |
| `contact_click`  | Нажатие на телефон, email, Telegram, WhatsApp или Viber                                                         |
| `file_download`  | Нажатие на ссылку с `download` или расширением PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, CSV, TXT, ZIP, RAR, 7Z        |
| `outbound_click` | Нажатие на HTTP/HTTPS-ссылку с другим origin                                                                    |
| `video_progress` | Первый запуск, 50% и завершение HTML5 `<video>`                                                                 |

Пороги, этапы видео и показы блоков отправляются один раз на текущем SPA-маршруте. Динамически добавленные элементы обнаруживаются автоматически. Активность продлевают движения/нажатия указателя, клавиатура, касания и прокрутка. `data-analog-ignore` на элементе или его предке исключает отслеживание элемента. DNT/GPC отключают отправку всех событий.

```html
<form id="request" data-analog-form="Заявка">...</form>
<section data-analog-view="Тарифы">...</section>
<video controls data-analog-video="Обзор продукта" src="/demo.mp4"></video>
```

После подтверждённой сервером успешной отправки формы вызовите:

```js
const form = document.querySelector("#request");
// В обработчике успешного ответа вашего приложения:
window.analog?.formSuccess(form);
```

Сам `submit` не считается успехом. Повторное подтверждение без нового изменения полей игнорируется; успех можно передать и без ранее обнаруженного начала. После нового изменения полей начинается следующий цикл. Не вызывайте `formSuccess` при ошибке или до проверки ответа сервера. Значения полей не собираются. Подпись формы/видео берётся из `data-analog-form` / `data-analog-video`, затем `id`, затем порядкового номера; используйте постоянные подписи для сопоставимой статистики.

`window.analog?.refresh()` повторно обнаруживает элементы после ручной подгрузки контента. API доступен после выполнения `tracker.js`; при DNT/GPC трекер не инициализируется, поэтому в примерах используется `?.`.

Для ссылок приоритет такой: явный `data-analog-event` → контакт → файл → внешний переход → обычный клик по внутренней ссылке. Нажатие создаёт одно событие. Telegram: `tg:`, `t.me`, `telegram.me` и их `www`-варианты. WhatsApp: `whatsapp:`, `wa.me`, `api.whatsapp.com`, `web.whatsapp.com`, `whatsapp.com`, `www.whatsapp.com`. Viber: `viber:`, `invite.viber.com`. Хосты сравниваются точно. Для контактов сохраняется только канал (`phone`, `email`, `telegram`, `whatsapp`, `viber`), без адресата и параметров. Для файлов/внешних ссылок — origin + pathname, без query, hash и учётных данных.

`POST /api/track?site_id=...` принимает новые типы с прежними общими полями. Дополнительные поля: `elementId` (до 120 символов), `threshold` (порог прокрутки/секунд), `stage` (`start`, `half`, `complete`), `channel` (канал контакта), `linkUrl` (HTTP/HTTPS URL до 1024 символов). Порог, этап, канал и ссылка обязательны для соответствующих типов. Сервер проверяет допустимые значения, удаляет параметры/фрагмент ссылок и не сохраняет неизвестные поля. Сохраняются существующие проверки origin/site, лимит 4096 байт, ограничение частоты запросов и очередь Telegram.

Новые события используют общий шаблон сайта или стандартное оформление. В шаблонах доступны `{element_id}`, `{threshold}`, `{stage}`, `{channel}`, `{link_url}`; `{element}` по-прежнему содержит подпись, `{action}` и `{action_emoji}` соответствуют типу. `{stage}` и `{channel}` содержат перечисленные выше машинные значения; стандартные уведомления показывают переведённые названия. Отдельные шаблоны просмотров/кликов применяются только к своим типам.

`form_abandon` означает отсутствие зафиксированного подтверждения при уходе, а не доказанный отказ от заявки. При закрытии браузера доставка не гарантируется. Скачивание означает нажатие, а не подтверждение сохранения файла. Видео в iframe (YouTube/Vimeo) не отслеживается; периодические сводки не отправляются.

### Additional events (English)

The tracker automatically records form starts, confirmed form successes, unfinished forms on page/SPA departure, scroll depth (25/50/75/100%), active time (30/60/120/300 seconds), marked block visibility, contact clicks, file download clicks, outbound links and HTML5 video milestones (start/half/complete). Telegram has independent per-site toggles; only successful forms and contacts notify by default. Other events remain in statistics. Existing page-view/click preferences are preserved.

Mark blocks with `data-analog-view`, optionally name forms/videos using `data-analog-form` / `data-analog-video`, and call `window.analog?.formSuccess(formElement)` only after your application confirms success. Submitting alone is not success. Duplicate confirmations are ignored until another field change. `window.analog?.refresh()` rescans dynamic content. DNT/GPC and `data-analog-ignore` are respected; field values and contact recipients are not collected.

Active time requires a visible tab and interaction within the previous 30 seconds. Blocks require 50% visibility for one continuous second. Milestones reset on SPA path changes. Explicit `data-analog-event` clicks override automatic link classification; contacts take priority over downloads and outbound links. Link URLs retain only origin/pathname. Download events indicate clicks, unfinished forms indicate missing confirmation, and delivery on browser closure is best effort. Embedded iframe players and scheduled digests are outside this version.

New event metadata uses `elementId`, `threshold`, `stage`, `channel`, `linkUrl`; the corresponding template variables are `{element_id}`, `{threshold}`, `{stage}`, `{channel}`, `{link_url}`. Common site templates apply to new types. Statistics report event counts, not unique visitors, with milestone breakdowns for scroll, active time and video.

### Подсказки команд Telegram

При запуске сервер регистрирует команды `/start` (запуск бота), `/menu` (главное меню) и `/cancel` (отмена действия), а также кнопку меню рядом с полем сообщения. Подсказки доступны в личном чате владельца; описания — русские по умолчанию и английские для языка Telegram `en`. После обновления перезапустите сервер и откройте чат с ботом: список появится при вводе `/` или нажатии кнопки меню. При временной ошибке Telegram регистрация повторяется перед запуском polling.

### Язык бота

В главном меню откройте «⚙️ Настройки» и выберите «Русский» или «English». Выбор владельца хранится в БД, сохраняется после перезапуска и применяется к меню, предпросмотрам, подсказкам команд и новым уведомлениям. Уже отправленные сообщения не переводятся. До первого выбора меню использует язык Telegram, а фоновые уведомления — `TELEGRAM_LOCALE` (по умолчанию русский). Пользовательские тексты шаблонов остаются как написаны. Если Telegram временно не принимает обновление подсказок команд, выбор языка сохраняется; подсказки синхронизируются при следующем выборе или перезапуске.
